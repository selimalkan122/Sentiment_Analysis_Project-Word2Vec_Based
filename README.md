# Yelp Review Sentiment Analysis

##  Project Overview
This project was developed to practically apply and deepen knowledge of various Natural Language Processing (NLP) techniques learned in the Text and Web Mining course. The primary objective is to analyze user reviews from Yelp and classify their underlying sentiments into three distinct categories: **Negative, Neutral, and Positive**.

##  Key Features and Methodology

This project goes beyond standard classification by comparatively exploring complex NLP and machine learning pipelines:

* **Custom-Trained vs. Pre-Trained Word2Vec:** Although various pre-trained Word2Vec models were tested during the development phase, the best results were achieved by training a custom Word2Vec model from scratch on the dataset. This approach captured the specific jargon and casual nuances of Yelp reviews much better than generalized pre-trained embeddings.
* **Context-Aware Text Processing (VADER vs. Word2Vec):** To maximize the effectiveness of the VADER sentiment lexicon (which relies heavily on punctuation, capitalization, and intensity modifiers), reviews were **intentionally left raw and uncleaned** for VADER scoring. Conversely, a rigorous text cleaning pipeline (including POS-tag-aware lemmatization) was applied to train the Word2Vec embeddings.
* **Hybrid Feature Engineering:** TF-IDF weighted Word2Vec embeddings were concatenated with the multi-dimensional sentiment scores generated by VADER, creating a robust, hybrid feature matrix.
* **Handling Class Imbalance:** **SMOTE** (Synthetic Minority Over-sampling Technique) was implemented to tackle dataset imbalance. To strictly prevent data leakage during cross-validation, SMOTE was securely integrated using the `imblearn` Pipeline structure.
* **Comprehensive Combinatorial Benchmarking:** The project evaluates not just models, but feature combinations. The following configurations were benchmarked using Logistic Regression, SGD (Faster SVM), Random Forest, and XGBoost:
  1. Only Word2Vec
  2. Word2Vec + SMOTE
  3. Word2Vec + VADER (Hybrid)
  4. Hybrid + SMOTE
* **Modular Architecture:** Following clean code principles, the pipeline is separated into distinct, maintainable modules (data loading, preprocessing, feature extraction, and modeling).

##  Limitations and Future Work

During the evaluation phase, it was observed that the **Neutral** class frequently gets confused with both **Positive** and **Negative** classes. This overlap is due to the inherent limitations of Word2Vec and the rule-based VADER algorithm, which struggle to fully capture deep contextual nuances, sarcasm, and complex semantic relationships within a sentence.

For future iterations, there is a plan to integrate **Transformer-based architectures (such as BERT or RoBERTa)** to significantly enhance the model's contextual understanding and resolve this misclassification issue.
